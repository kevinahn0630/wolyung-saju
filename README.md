# 월영아씨 사주 소개팅

서울권 대학생을 대상으로 한 사주 기반 소개팅 MVP 프론트 프로토타입입니다.
현재 버전은 랜딩 → 스텝형 입력 → 사주 기반 연애운 풀이까지 동작하고, 신청서는 Cloudflare D1 에 저장됩니다. 실제 매칭과 사진 업로드, 결제는 아직 연결되어 있지 않습니다.

## 데모

- 운영 중: https://wolyungdang.com (Cloudflare Workers, D1 은 APAC 리전)
- 옛 링크: https://wolyung-saju.clearlean01.chatgpt.site (OpenAI Sites, `clearlean01` 계정 소유)

커스텀 도메인을 붙이면서 `*.workers.dev` 주소는 꺼졌습니다. 아래 배포 항목을 보세요.

## 실행

```bash
npm install
cp .dev.vars.example .dev.vars   # ADMIN_PASSWORD 를 채우세요
npm run dev
```

로컬 개발 서버는 기본적으로 `http://localhost:3000`에서 열립니다. 관리자 화면은 `http://localhost:3000/admin` 입니다.

`.dev.vars` 를 바꾸면 개발 서버를 다시 띄워야 반영됩니다.

## 빌드

```bash
npm run build
```

## 배포

두 갈래가 다 살아 있습니다. `.env` 가 없으면 OpenAI Sites 쪽 자리표시자를 그대로 쓰고, 있으면 그 값으로 자기 Cloudflare 계정에 붙습니다. 갈라지는 지점은 `vite.config.ts` 한 곳입니다.

### Cloudflare Workers (현재 운영 방식)

처음 한 번만:

```bash
npx wrangler login
```

D1 을 만들고 나온 `database_id` 를 `.env` 에 적습니다 (`.env.example` 참고).

```bash
npx wrangler d1 create wolyung-saju
```

스키마를 올립니다. `migrations_dir` 이 생성된 설정 기준 경로라 **빌드를 먼저** 해야 합니다.

```bash
npm run build && npx wrangler d1 migrations apply wolyung-saju --remote --config dist/server/wrangler.json
```

관리자 비밀번호는 파일이 아니라 시크릿으로 넣습니다.

```bash
npx wrangler secret put ADMIN_PASSWORD --config dist/server/wrangler.json
```

배포합니다.

```bash
npm run build && npx wrangler deploy --config dist/server/wrangler.json
```

커스텀 도메인은 `.env` 의 `CF_CUSTOM_DOMAINS` 에 쉼표로 적습니다. 해당 도메인이 이 Cloudflare 계정의 영역(zone)으로 들어와 있으면 배포할 때 DNS 와 인증서까지 알아서 잡힙니다.

**이 값을 넣으면 `*.workers.dev` 주소는 꺼집니다.** wrangler 가 라우트를 가진 배포에서는 `workers_dev` 를 기본으로 끄기 때문입니다. 버전별 미리보기 주소(`preview_urls`)도 같이 꺼집니다. 둘 다 살리고 싶으면 설정에 `workers_dev: true` 를 명시해야 합니다.

운영 중인 D1 은 `wrangler` 로 직접 들여다볼 수 있습니다.

```bash
npx wrangler d1 execute wolyung-saju --remote --config dist/server/wrangler.json --command "SELECT COUNT(*) FROM submissions"
```

한글이 든 SQL 을 셸에서 직접 넘기면 Windows 에서 인코딩이 깨집니다. 한글을 비교하거나 넣어야 하면 UTF-8 파일로 저장해 `--file` 로 넘기세요.

### OpenAI Sites

`.env` 없이 ChatGPT 에서 "이 프로젝트를 Sites 로 배포해줘" 하면 됩니다. `.openai/hosting.json` 의 `project_id` 가 가리키는 계정이 소유자이고, D1 도 그 계정에 딸려 잡힙니다. 그쪽 D1 은 `wrangler` 로 붙을 수 없어서 자료를 빼내려면 `/admin` 의 CSV 내보내기를 써야 합니다.

## 사주 계산 방식

`lib/saju/` 안에 있습니다. 만세력 표를 들고 있지 않고 태양 위치를 직접 계산합니다.

- **연주** — 입춘(태양 황경 315°)에 바뀝니다. 양력 1월생과 입춘 전 2월생은 전년도 간지입니다.
- **월주** — 달력의 월이 아니라 절기로 나뉩니다. 출생 순간의 태양 황경을 30° 구간으로 끊어 월지를 정하고, 연간에 오호둔을 적용해 월간을 얻습니다.
- **일주** — 율리우스일 기반 60갑자입니다. 기준점은 2000-01-01 = 戊午일이고, 진태양시 자정에 바뀝니다.
- **시주** — 일간에 오자둔을 적용합니다. 23시~01시가 자시입니다.
- **시각 보정** — 한국 표준시가 UTC+8:30이던 구간과 역대 서머타임을 되돌린 뒤, 서울 경도(126.98°) 기준 진태양시 보정 −32분을 적용합니다. 균시차는 국내 만세력 관행에 맞춰 적용하지 않습니다.

태양 황경은 Meeus 『Astronomical Algorithms』 25장 저정밀 공식을 씁니다. 오차는 약 0.01°로, 절기 경계에서 ±15분 수준입니다. 절기가 바뀌는 순간에 15분 이내로 붙어 태어난 경우가 아니면 결과에 영향이 없습니다.

검증한 값 — 입춘 2025 (계산 02-03 23:07 / 한국천문연구원 23:10), 일주 2000-01-01 = 戊午, 2003-05-17 13:20 = 癸未 丁巳 庚寅 壬午.

## 데이터 저장

`.openai/hosting.json` 의 `"d1"` 값이 바인딩 이름이 됩니다. 현재 `"DB"` 로 켜 두었습니다.

- 스키마: `migrations/` 아래 번호순으로 쌓입니다. 현재 0004 까지입니다.
- 학번(`student_id`), 환불 은행(`refund_bank`), 환불 계좌번호(`refund_account`)를 인스타그램 아이디 단계에서 받습니다. 은행은 `lib/wolyung-flow.ts` 의 `REFUND_BANKS` 목록에 있는 이름만 받고, 계좌번호는 하이픈을 걷어 낸 숫자만 저장합니다. 이 열이 생기기 전 신청서는 비어 있습니다.
- 받는 학교는 서울대·연세대·고려대·서강대·성균관대·한양대·이화여대 일곱 곳입니다.
- 학교는 화면 문구가 아니라 코드값(`snu` / `yonsei` / `korea` / `sogang` / `skku` / `hanyang` / `ewha`)으로 저장합니다. 나중에 학교로 매칭을 걸 때 표기가 흔들리지 않게 하려는 것입니다. 늘리려면 `lib/wolyung-flow.ts` 의 `UNIVERSITIES` 에 한 줄 더하면 됩니다. 서버 허용 목록도 이 표에서 만들어집니다.
- 로컬 개발에서는 API 라우트가 같은 스키마를 `CREATE TABLE IF NOT EXISTS` 로 만들어 두므로 따로 마이그레이션을 돌리지 않아도 됩니다.
- 배포 환경에는 `wrangler d1 migrations apply` 로 적용해야 합니다. 자세한 건 위 배포 항목에 있습니다.
- 같은 인스타그램 아이디로 다시 제출하면 기존 행을 덮어씁니다.
- 나중에 매칭 쿼리를 바로 걸 수 있도록 원본 입력과 함께 계산된 네 기둥과 오행 분포도 같이 저장합니다.

## 개인정보

수집·이용 동의를 받지 않으면 저장되지 않습니다. 서버도 `consentAgreed !== true` 인 요청을 400 으로 돌려보냅니다.

- 문구는 `lib/consent.ts` 한 곳에 있습니다. 고칠 때 `CONSENT_VERSION` 도 함께 올리세요. 신청서에는 동의한 버전이 남아서, 나중에 "이 사람이 무엇에 동의했는지" 를 되짚을 수 있습니다.
- 고지한 보유 기간은 **매칭 종료 후 6개월** 입니다.
- 매칭 상대에게 공개한다고 고지한 항목은 **인스타그램 아이디, 재학중인 대학교, 학과** 세 가지입니다. 이름·생년월일·태어난 시간·학번·환불 계좌는 제공하지 않는다고 적어 두었으니, 매칭 결과 화면을 만들 때 이 셋만 내보내야 합니다.
- **환불 계좌는 환불이 끝나거나 환불할 일이 없어지면 지체 없이 파기한다고 고지했습니다.** 매칭 종료 후 6개월보다 먼저 지워야 합니다. 관리자 목록에는 뒤 4자리만 보이고, 전체 번호는 CSV 내보내기에서만 나옵니다.
- 학번의 이용 목적은 재학생 여부 확인으로 고지했습니다.
- 문의·삭제 요청 창구는 인스타그램 `@wolyungdang` 입니다. `CONTACT_HANDLE` 한 곳에만 있어서, 계정을 옮기면 여기만 고치면 동의 전문과 첫 화면 `문의` 버튼에 함께 반영됩니다.
- 삭제 요청이 오면 `/admin` 에서 해당 행을 지우면 됩니다.

## 관리자 화면

`/admin` 에서 신청서를 보고 지울 수 있습니다. 실명과 생년월일이 그대로 뜨는 화면이라 인증 없이는 아무것도 내려오지 않습니다.

- 비밀번호는 `ADMIN_PASSWORD` 환경변수에만 둡니다. 저장소에도 코드에도 없습니다.
- 값이 없으면 화면이 잠긴 채로 열리지 않습니다. 빈 비밀번호로 뚫리지 않습니다.
- 로컬: `.dev.vars.example` 을 `.dev.vars` 로 복사해 값을 채우세요. `.dev.vars` 는 커밋되지 않습니다.
- 배포: 파일이 아니라 시크릿으로 넣으세요.
- 세션은 만료 시각에 HMAC 서명을 붙인 HttpOnly 쿠키입니다. 서명 키가 비밀번호라, 비밀번호를 바꾸면 기존 세션이 전부 끊깁니다.
- 목록은 100건씩 끊어서 보여 줍니다. 한 번에 받아 갈 수 있는 최대치는 500건이고, 그 위 상수는 `app/api/admin/submissions/route.ts` 에 있습니다.

### CSV 내보내기

`/admin` 의 `CSV 내보내기` 는 `GET /api/admin/submissions?format=csv` 입니다. 목록과 같은 관리자 세션을 요구합니다.

지금처럼 Cloudflare 로 직접 배포하면 `wrangler d1 execute` 로도 붙을 수 있지만, 매칭을 돌릴 자료를 만들 때는 이쪽이 편합니다. OpenAI Sites 로 배포한 경우에는 플랫폼이 잡아 주는 D1 이라 wrangler 로 붙을 수 없어서 **이 내보내기가 자료를 빼내는 유일한 수단입니다.**

- 쪽 넘김과 무관하게 전체를 내려보냅니다 (상한 10,000건).
- 화면 표에 없는 `calendar_type`, `consent_agreed_at` 까지 담습니다. 나중에 매칭을 돌릴 때 아쉬운 열이 없게 하려는 것입니다.
- 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM 을 붙입니다. 값은 전부 큰따옴표로 감싸므로 이름에 쉼표나 따옴표가 들어 있어도 안전합니다.
- **실명과 생년월일이 그대로 담긴 파일입니다.** 내려받은 뒤 보관에 주의하고, 쓰임이 끝나면 지우세요.

## 스팸 방어

공개된 엔드포인트라 세 겹으로 막습니다.

1. 동의하지 않은 요청은 받지 않습니다.
2. 허니팟 — 화면 밖으로 밀어낸 미끼 항목이 채워져 오면 봇으로 보고, 성공한 척 응답하되 저장하지 않습니다.
3. IP 기준 제한 — 같은 IP 에서 시간당 5건까지만 받습니다. 넘으면 429 입니다.

IP 는 해시해서 `submission_attempts` 에 남기고 24시간 뒤 지웁니다. IPv4 는 경우의 수가 적어 해시만으로 되돌릴 수 있으므로, 이건 익명화가 아니라 원문 IP 를 적재하지 않기 위한 조치입니다.

한도(`RATE_LIMIT_PER_HOUR`)는 `app/api/submissions/route.ts` 위쪽에 있습니다. 학교 와이파이처럼 IP 를 공유하는 환경에서 정상 사용자가 막히면 이 값을 올리세요.

## 개발 인계 메모

문구를 고칠 때는 `lib/wolyung-flow.ts`(폼·화면 카피)와 `lib/love-reading.ts`(연애운 풀이)만 보면 됩니다. 연애운 풀이는 무작위 요소가 없어서 같은 사주면 언제나 같은 결과가 나옵니다. 나중에 모델 호출로 바꾸려면 `buildLoveReading` 의 시그니처를 유지한 채 내부만 갈아 끼우면 됩니다.

다음으로 붙일 일의 추천 순서입니다.

1. 매칭 로직 — 저장해 둔 일주·오행 분포로 궁합 점수를 매기는 방식
2. 매칭 결과 화면과 인스타그램 아이디 공개 시점 정하기
3. 보유 기간이 지난 신청서를 자동으로 지우는 정리 작업
4. 첫 매칭 무료, 추가 후보 보기 유료 여부 결정

사진 업로드와 음력 → 양력 변환은 이번 운영에서는 하지 않기로 했습니다.

매칭은 실시간이 아니라 모집을 닫고 한 번에 돌립니다. 모집을 마감한 뒤 이틀쯤 지나 매칭 결과를 내보내는 일정이라, 신청 화면은 접수 확인까지만 보여 주면 됩니다.
